## 阶段 1：把小镇放进 Astro 页面

- 把 `town/index.html` 里的游戏代码拆成模块（地形、物体、角色、碰撞、输入、绘制），放进 Astro 的新首页。
- 素材来自 `assets/normalized/`，放进 `public/`；布局来自 `layout.json`。
- 建造模式代码只在开发服务器里加载（`import.meta.env.DEV`），生产构建里整个去掉。
- 画布适配窗口大小（只管桌面，不做手机，2026-11-15 决定）。
- 结束时：本地 `npm run dev` 能玩，`npm run build` 通过，建造模式在开发环境可用。

## 阶段 2：入口里的内容（需要你先定）

- **入口内容的呈现已定**：屏幕中间打开一块木头告示板（右侧像素风滚动条、右上角叉、统一字体）。需要先做的素材和设计：木板面板的九宫格素材、滚动条的轨道和滑块、关闭的叉、全站字体。
- 做告示板组件（网页里的真实 HTML，用九宫格边框图拼出木板，自定义滚动条，Esc 和叉关闭，打开关闭动画）。
- 做 Projects（ChamberUp，含 Project Manager and Product Owner 的说明）、Stories（含 Darts 子页）、About Me 三个入口的内容页，沿用现有内容，换新样式。
- 磨坊保持"施工中"。
- 结束时：走到每个入口都能进、能返回。

## 阶段 6：决定

站点主人整站走一遍，和线上版对比：**合并上线，或删分支。**

## 每个阶段交付前我做的检查

- 浏览器控制台无报错；`npm run build` 通过。
- 碰撞：水岸、建筑边缘、树干走一遍；点击移动被挡住时能停下。
- 任何改动素材的步骤：重新跑 `normalize.py run`，在镇子里看像素粗细、颜色、尺寸是否仍然统一（见 `ART_BIBLE_v1.md` 第 10 节检查表）。
- 留言板相关：不写线上数据库。
- 只在 `v2` 分支提交；`git status` 里 `docs/v2/` 保持未跟踪。

## 风险

| 风险 | 对策 |
|---|---|
| 素材风格漂移（ChatGPT 每次生成都不一样） | 美术标准加统一处理程序；新素材一律新开对话，附标准样图；处理后在镇子里看，不搭就重生成 |
| 入口内容呈现还没想好，阶段 2 会卡住 | 阶段 1 结束前先和站点主人定第 6 节第 1 条 |
| 桌面性能 | 地面预渲染，只画可见部分；阶段 4 实测；必要时降低物体数量或像素缩放（手机不做） |
| 画布内容搜索引擎读不到 | 语义化 HTML 备用导航，文字内容在 DOM 里 |
| 素材版权的灰区 | 上线前再核对 OpenAI 使用条款；不用任何游戏的现成素材和名字 |
| 范围蔓延（钓鱼、季节、动物、地形编辑都很诱人） | 一律先记在 PRD 的"以后的版本"，不在阶段中途加 |
